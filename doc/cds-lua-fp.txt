                                                                    *cds-lua-fp*
cds-lua-fp is a small functional vocabulary for Lua: |cds.fp| for lists,
|cds.result| for Lua's own error convention (a function answers `value`,
or `nil, err`, and only nil fails), |cds.module|, a fallback a module
returns through so that a name it does not have fails at the call, in
words, and |cds.needs|, a check a program runs at startup against the
libraries installed. The four files use nothing beyond the standard
library, so they run on Lua 5.1 and up, under LuaJIT and inside Neovim
alike.

Install it as a rock, `luarocks install cds-lua-fp`, or as a lazy.nvim
plugin, `{ "cds-io/cds-lua-fp", lazy = true }`; cds-lua, a Neovim library
built on it, declares it as a dependency.

  Lists ............................................................. |cds.fp|
  The Result convention ......................................... |cds.result|
  Names a module does not have .................................. |cds.module|
  Taking the library ............................................. |cds.needs|

                                                                        *cds.fp*
The list helpers: map, filter, reduce, find, find_map, any, all, set and
unique. They exist because pure Lua 5.1 builds none of these in, and code
meant to run outside Neovim has no vim.iter. A list is a sequence (items at 1..n,
no holes), read with ipairs. Map, filter and unique return fresh lists,
set a fresh table, reduce the final accumulator, find the item, any and
all a boolean; none modifies the input list. The function argument comes
last, so one written out over several lines reads as a block.

------------------------------------------------------------------------------
                                                                  *cds.fp.map()*
                             `fp.map`({list}, {fn})
Builds the list of fn(item, index) for each item, in order. A nil result is
an error: it would leave a hole, and ipairs would stop reading the list
there.
Parameters ~
{list} `(T[])`
{fn} `(fun(item: T, index: integer): U)`
Return ~
`(U[])`

------------------------------------------------------------------------------
                                                               *cds.fp.filter()*
                          `fp.filter`({list}, {keep})
Keeps the items for which keep(item, index) is true, in order.
Parameters ~
{list} `(T[])`
{keep} `(fun(item: T, index: integer): any)`
Return ~
`(T[])`

------------------------------------------------------------------------------
                                                               *cds.fp.reduce()*
                      `fp.reduce`({list}, {initial}, {fn})
Folds the items into one value, left to right: the result of fn(value, item,
index) is the value the next item meets, starting from `initial`, which is
also what an empty list gives.
Parameters ~
{list} `(T[])`
{initial} `(A)`
{fn} `(fun(value: A, item: T, index: integer): A)`
Return ~
`(A)`

------------------------------------------------------------------------------
                                                                 *cds.fp.find()*
                           `fp.find`({list}, {test})
Finds the first item for which test(item, index) is truthy and answers it
with its index; nil when none is. The lists here hold nodes, strings and
records, never false, so a falsy answer means no item.
Parameters ~
{list} `(T[])`
{test} `(fun(item: T, index: integer): any)`
Return ~
`(T?)` item
`(integer?)` index

------------------------------------------------------------------------------
                                                             *cds.fp.find_map()*
                          `fp.find_map`({list}, {fn})
Answers the first non-nil fn(item, index), stopping there; nil when every
item answers nil. One pass that finds and transforms at once, for a chain of
parsers tried in order: the first that reads the line gives the record.
Parameters ~
{list} `(T[])`
{fn} `(fun(item: T, index: integer): U?)`
Return ~
`(U?)`

------------------------------------------------------------------------------
                                                             *cds.fp.flat_map()*
                          `fp.flat_map`({list}, {fn})
Joins the lists fn(item, index) answers, in order: a map whose answers are
lists, flattened one level.
Parameters ~
{list} `(T[])`
{fn} `(fun(item: T, index: integer): U[])`
Return ~
`(U[])`

------------------------------------------------------------------------------
                                                                 *cds.fp.keys()*
                                 `fp.keys`({t})
Lists the keys of a table, in no particular order; sort it when the order
matters.
Parameters ~
{t} `(table<K, any>)`
Return ~
`(K[])`

------------------------------------------------------------------------------
                                                                 *cds.fp.each()*
                            `fp.each`({list}, {fn})
Calls fn(item, index) for each item, in order, for what it does; the answers
are dropped. Where map builds a list, each performs an action per item: a
cursor set in every window showing a buffer.
Parameters ~
{list} `(T[])`
{fn} `(fun(item: T, index: integer))`

------------------------------------------------------------------------------
                                                           *cds.fp.filter_map()*
                         `fp.filter_map`({list}, {fn})
Keeps every non-nil fn(item, index), in order. One pass that filters and
transforms at once, for a reading that keeps what it can parse: the heading
each line carries, for the lines that carry one.
Parameters ~
{list} `(T[])`
{fn} `(fun(item: T, index: integer): U?)`
Return ~
`(U[])`

------------------------------------------------------------------------------
                                                                  *cds.fp.any()*
                            `fp.any`({list}, {test})
Does test(item, index) hold for some item? Stops at the first.
Parameters ~
{list} `(T[])`
{test} `(fun(item: T, index: integer): any)`
Return ~
`(boolean)`

------------------------------------------------------------------------------
                                                                  *cds.fp.all()*
                            `fp.all`({list}, {test})
Does test(item, index) hold for every item? Stops at the first that
fails; true for an empty list.
Parameters ~
{list} `(T[])`
{test} `(fun(item: T, index: integer): any)`
Return ~
`(boolean)`

------------------------------------------------------------------------------
                                                                  *cds.fp.set()*
                            `fp.set`({list}, {key})
Builds a set of the items: a table of each one's key to true.
Parameters ~
{list} `(T[])`
{key} `(optional)` `(fun(item: T, index: integer): any)` the item itself without one
Return ~
`(table<any, true>)`

------------------------------------------------------------------------------
                                                               *cds.fp.unique()*
                           `fp.unique`({list}, {key})
Keeps the items whose key has not appeared before, in order: the first of
each.
Parameters ~
{list} `(T[])`
{key} `(optional)` `(fun(item: T, index: integer): any)` the item itself without one
Return ~
`(T[])`


==============================================================================
                                                                    *cds.result*
Composes Lua's own error convention: a function answers `value`, or
`nil, err`, and only nil fails, so false and zero are valid successful
values. A step that can refuse goes through `bind` or `traverse`; one that
cannot goes through `map`, so a reader can tell the two apart at the call.
Where a step cannot fail and there is no error to carry, |cds.fp.map()| is
the plain list map. Errors are values until the dispatch rim turns the
last one into a message for the reader.

------------------------------------------------------------------------------
                                                             *cds.result.bind()*
                      `result.bind`({value}, {err}, {fn})
Passes the value through `fn`, which may refuse (nil, err), and an error
through untouched.
Parameters ~
{value} `(T?)`
{err} `(any)`
{fn} `(fun(value: T): U?, any)`
Return ~
`(U?)` value
`(any)` err

------------------------------------------------------------------------------
                                                                *cds.result.map*
                                  `result.map`
Passes the value through `fn`, which always answers, and an error through
untouched. The same step as bind: the name says at the call whether `fn` can
refuse.

------------------------------------------------------------------------------
                                                          *cds.result.context()*
                   `result.context`({value}, {err}, {prefix})
Passes the value through untouched and puts `prefix` in front of an error,
so a failure deep in a pipeline says where it was met ('Parse error in "A
and": ...').
Parameters ~
{value} `(T?)`
{err} `(string?)`
{prefix} `(string)`
Return ~
`(T?)` value
`(string?)` err

------------------------------------------------------------------------------
                                                         *cds.result.traverse()*
                       `result.traverse`({values}, {fn})
Runs fn(value, index) over every item, stopping at the first refusal, and
answers the list of answers, or nil and that error.
Parameters ~
{values} `(T[])`
{fn} `(fun(value: T, index: integer): U?, any)`
Return ~
`(U[]?)` values
`(any)` err


==============================================================================
                                                                    *cds.module*
Every module of the library returns through |cds.module.wrap()|, so a
name a module does not have fails at the call with the module's name and
the key in words, where plain Lua says "attempt to call field 'filter_mop'
(a nil value)" somewhere later. The usual cause is a cds-lua older than the
code calling it, and the message says so.

A lookup on a module therefore answers a function for every name. A test
for a name's presence asks |cds.module.is_fallback()| of what the lookup
answered, as cds.needs does; `rawget` would miss a module whose names come
through a metatable of its own, as vim.async's do.

A module ends with >lua

  return require("cds.module").wrap("fp", M)
<
and declares `---@class cds.fp` above its table, so the language server
carries the module's type to every caller and a misspelt name is an
undefined field at edit time. The named function is the form: a `__call`
metamethod in its place loses the type.

------------------------------------------------------------------------------
                                                             *cds.module.wrap()*
                          `module.wrap`({name}, {mod})
Puts the fallback behind the module and answers the module.
Parameters ~
{name} `(string)` "fp", "html.blocks"
{mod} `(T)`
Return ~
`(T)`

------------------------------------------------------------------------------
                                                      *cds.module.is_fallback()*
                         `module.is_fallback`({value})
Whether a value is one of the fallbacks: what a module answered for a
name it does not have.
Parameters ~
{value} `(any)`
Return ~
`(boolean)`

                                                                     *cds.needs*
A plugin takes the library as a lazy.nvim dependency, declared in the
`lazy.lua` at its root: >lua

  return {
    "cds-io/<plugin>",
    dependencies = { { "cds-io/cds-lua", lazy = true } },
  }
<
The dependency tracks `main` with no pin, so one `:Lazy update` moves every
plugin that depends on it together, and one copy of `lua/cds/` is on the
runtimepath, so `require("cds.fp")` has one file to resolve to.

What the plugin calls is declared in `lua/<plugin>/needs.lua`, by module
and name: a function, or a table such as `http.status`. >lua

  ---@type cds.needs.Capabilities
  return {
    fp = { "map", "filter" },
    http = { "request", "status" },
  }
<
The plugin's entry runs |cds.needs.check()| first and refuses the whole
plugin, in one message naming the remedy, when the libraries installed lack
a name; the message names the library each name belongs to, this rock for
`fp`, `result`, `module` and `needs`, cds-lua for the rest. Its spec harness wraps the declared modules through
|cds.needs.strict()|, so a call the declaration leaves out fails the spec
in words, and the declaration stays what the code uses.

The one check a plugin keeps for itself is whether this module loads: a
library too old to carry it fails that `require`, which is the answer.

------------------------------------------------------------------------------
Alias ~
{cds.needs.Capabilities} `(table<string, string[]>)` cds module to the functions used

------------------------------------------------------------------------------
                                                           *cds.needs.missing()*
                        `needs.missing`({capabilities})
Lists the capabilities the library present lacks, as "fp.filter" names,
modules in name order and each in declaration order: a name the module has
nothing under, or every name of a module that does not load.
Parameters ~
{capabilities} `(cds.needs.Capabilities)`
Return ~
`(string[])`

------------------------------------------------------------------------------
                                                             *cds.needs.check()*
                    `needs.check`({plugin}, {capabilities})
Answers nil when everything declared is here; otherwise one sentence for the
reader, naming the plugin, the missing functions and the remedy, by the
library each function belongs to: "a.nvim needs cds-lua-fp with
fp.filter_mop and cds-lua with redraw.places: install or update
cds-io/cds-lua-fp and cds-io/cds-lua".
Parameters ~
{plugin} `(string)` truth-table.nvim
{capabilities} `(cds.needs.Capabilities)`
Return ~
`(string|nil)`

------------------------------------------------------------------------------
                                                            *cds.needs.strict()*
                    `needs.strict`({plugin}, {capabilities})
Replaces each declared module, in package.loaded, with a proxy that holds
nothing itself: a declared name reads from the real module, so a seam a spec
replaces there (`proc.runner`) is what the plugin's own code reads; any
other name raises, naming the plugin whose declaration is short; a write
goes to the real module, since a plugin setting a hook the module leaves nil
(`http.trace`) is not declaring a name it reads. The library's own modules
pass through, since they use each other beyond the declaration; a module the
tier cannot load (one that needs `vim`, under plain busted) is left alone.
For a spec harness, before any spec runs.
Parameters ~
{plugin} `(string)`
{capabilities} `(cds.needs.Capabilities)`
